# metalparser

Сбор **действующих** компаний, у которых **основной ОКВЭД** связан с
металлообработкой, из дампа **ЕГРЮЛ ФНС**, с дообогащением контактов
(телефоны / почты / сайты) через **checko.ru**. Выгрузка в **CSV**, **Excel**
и просмотр через **веб-интерфейс**.

Собираемые поля: название, ИНН, ОГРН, основной ОКВЭД и его расшифровка
(вид деятельности), регион, статус, адрес, телефон(ы), почта(ы), сайт(ы).

## Почему такая архитектура

- **Список компаний** берётся из ЕГРЮЛ: только так можно получить *все*
  юрлица по основному ОКВЭД и статусу. Каталог checko/аналогов в вебе обычно
  ограничен первыми ~1000 результатами и жёстко режет частые запросы (429).
- **Контактов в ЕГРЮЛ нет** — телефоны/почты/сайты добавляются отдельным шагом
  через checko (API при наличии ключа, иначе HTML).

### Где взять дамп ЕГРЮЛ

Полный реестр ФНС отдаёт по платной годовой подписке «Интеграция сведений
ЕГРЮЛ/ЕГРИП» (nalog.gov.ru). Бесплатный раздел `nalog.gov.ru/opendata`
содержит только отдельные срезы (без полного реестра с ОКВЭД). Альтернатива —
готовая база у поставщиков (напр. ofdata.ru). Парсер принимает дамп как есть:
файл `.xml`, архив `.zip` (в т.ч. zip-в-zip) или папку с файлами.

## Установка

```bash
pip install -r requirements.txt
```

## Запуск из консоли (CLI)

```bash
# только данные ЕГРЮЛ (без контактов), ядро ОКВЭД 24/25/28.4, действующие
python -m metalparser.cli /path/to/egrul.zip --no-enrich

# с дообогащением контактов через API checko
export CHECKO_API_KEY=ваш_ключ
python -m metalparser.cli /path/to/egrul/ --csv metal.csv --xlsx metal.xlsx

# HTML-режим checko (без ключа; медленно, возможен 429)
python -m metalparser.cli /path/to/egrul.xml --html --delay 3
```

Основные ключи:

| Ключ | Назначение |
|------|------------|
| `--okved-set {core,narrow,wide}` | набор основных ОКВЭД (по умолчанию `core` = 24, 25, 28.4) |
| `--okved 28.41` | добавить произвольный префикс ОКВЭД (можно повторять) |
| `--all-statuses` | не фильтровать по статусу (по умолчанию только действующие) |
| `--no-enrich` | не обращаться к checko (только поля ЕГРЮЛ) |
| `--html` | принудительный HTML-режим checko |
| `--api-key` / env `CHECKO_API_KEY` | ключ API checko |
| `--delay` | пауза между запросами к checko, сек (по умолчанию 1.5) |
| `--limit N` | ограничить число компаний (для проб) |
| `--csv` / `--xlsx` / `--no-xlsx` | пути выгрузки |

Наборы ОКВЭД (`metalparser/okved.py`):
- `core` — **24** (металлургия), **25** (готовые металлоизделия, вкл. **25.62**
  мехобработку), **28.4** (металлообрабатывающие станки);
- `narrow` — только **25.5–25.9** (прямая обработка металла);
- `wide` — `core` + **46.72** (опт. торговля металлами) + **33.11** (ремонт).

## Режим без дампа: `--source api` (только ключ checko)

Если есть ключ checko, дамп ЕГРЮЛ не нужен: список компаний перечисляется через
`/v2/search` по ОКВЭД (с фильтром «действующие» и регионом), затем по каждому
ИНН через `/v2/company` берутся полные данные и контакты. Остаются только
компании, у которых **основной** ОКВЭД из целевых групп (пост-фильтр).

```bash
export CHECKO_API_KEY=ваш_ключ
# вся РФ, ядро 24/25/28.4, действующие:
python -m metalparser.cli --source api --csv metal.csv
# начать только с класса 24 (none = без пресета, перебираем коды 24.*):
python -m metalparser.cli --source api --okved-set none --okved 24 --limit 200
# ограничить регионами (коды):
python -m metalparser.cli --source api --region 77 --region 50 --limit 200
```

checko `/v2/search` ищет по **точному коду-группе** (XX.XX), а не по префиксу
(проверено: `25.6` → 0, `25.62` → тысячи). Поэтому префиксы 24/25/28.4
разворачиваются в конкретные коды из справочника `METAL_GROUP_CODES`
(`okved.py`). Фильтр «только действующие» применяется и в поиске (`active=true`),
и пост-фильтром по статусу из `/v2/company`.

Учитывайте: каждая страница поиска и каждый запрос компании тратят квоту тарифа;
по «всей РФ» поиск может упираться в потолок пагинации — тогда разбивайте по
регионам (`--region`).

### Калибровка API под ваш ключ

Точные имена параметров `/v2/search` и пути в JSON могут отличаться от заданных
по умолчанию. Зонд печатает реальные ответы — по ним правится один блок констант
в `metalparser/checko.py` (секция «Калибруемая схема /v2/search» и `COMPANY_*`):

```bash
export CHECKO_API_KEY=ваш_ключ
python scripts/probe_checko.py
# при необходимости подставить параметры из доки:
python scripts/probe_checko.py --param by=оквэд --param query=25 --param region=77
```

## Режим без API-лимита: `--source site` (каталог checko по кукам)

Собирает данные с **сайта** checko (HTML), минуя API и его дневной лимит.
Каталог по коду ОКВЭД (`/company/select?code=<6 цифр>`, ~50 компаний/страницу)
→ карточки компаний → имя/ИНН/контакты. Для открытых контактов и полного
каталога нужны **куки авторизованного аккаунта** checko.

```bash
# куки берутся из браузера (DevTools → Network → Request Headers → Cookie)
export CHECKO_COOKIE='полная_строка_cookie'
python -m metalparser.cli --source site --okved-set none --okved 25.62 --limit 50 --csv site.csv
```

Особенности: код кодируется 6 знаками без точек (25.62 → 256200); ставьте
разумную паузу `--delay` (по умолчанию 2 с) — сайт режет частые запросы;
каталог может быть ограничен по глубине пагинации. Статус «действующая»
определяется по карточке (пост-фильтр). Куки — секрет, храните в переменной
окружения, не в коде. При 429 клиент сам замедляется; собранное пишется в CSV
потоково, повторный запуск с тем же `--csv` **докачивает** пропущенных.

### Режим настоящего браузера (`--browser`)

Надёжнее против блокировок: запросы идёт реальный Chromium (Playwright) —
полные заголовки, JS, ваша сессия. Установка на сервере (один раз):

```bash
pip install playwright
playwright install chromium
```

Авторизация — либо куки (`CHECKO_COOKIE`), либо разовый вход в браузере с
сохранением профиля:

```bash
python scripts/browser_login.py          # откроется окно — войдите в checko
python -m metalparser.cli --source site --browser --okved-set none --okved 25.62 \
       --delay 3 --csv site.csv
```

Профиль хранится в `data/browser_profile` (env `CHECKO_PROFILE`). Headless
по умолчанию; `CHECKO_HEADLESS=0` — показать окно. Если Chromium предустановлен
в нестандартном месте — путь в `PLAYWRIGHT_CHROME`.

## Веб-интерфейс (закрытый раздел по паролю)

Раздел защищён логином: все маршруты доступны только после входа.
Пароль задаётся переменной окружения `PARSER_PASSWORD` (без неё вход закрыт).

```bash
export PARSER_PASSWORD='придумайте_пароль'   # обязательно
export PARSER_USERNAME='admin'               # необязательно (по умолчанию admin)
export SECRET_KEY="$(python -c 'import secrets;print(secrets.token_hex(32))')"
python -m webapp.app                          # http://127.0.0.1:5000
```

Открыть `http://127.0.0.1:5000` → страница входа → ввести логин/пароль →
форма парсера. Кнопка «Выход» в правом верхнем углу завершает сессию.

Форма позволяет указать путь к дампу, набор ОКВЭД, статус, режим обогащения,
лимит; показывает прогресс и таблицу, даёт скачать CSV/Excel.

### Деплой как раздел на parsercompressor.online

Боевой запуск под gunicorn:

```bash
export PARSER_PASSWORD='...' SECRET_KEY='...'
gunicorn -w 2 -b 127.0.0.1:8001 webapp.app:app
```

Вариант А — **поддомен** `parser.parsercompressor.online` (nginx):

```nginx
server {
    server_name parser.parsercompressor.online;
    location / {
        proxy_pass http://127.0.0.1:8001;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Вариант Б — **подпуть** `parsercompressor.online/parser` (nginx):

```nginx
location /parser/ {
    proxy_pass http://127.0.0.1:8001/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Prefix /parser;   # ProxyFix учитывает префикс
}
```

Приложение уже обёрнуто в `ProxyFix`, поэтому при работе за nginx с заголовком
`X-Forwarded-Prefix` ссылки/редиректы строятся правильно. Обязательно выдайте
домену HTTPS (сертификат), т.к. пароль и сессионная кука должны идти по TLS.

## Структура проекта

```
metalparser/
  okved.py     набор ОКВЭД и иерархическое сопоставление по префиксу
  egrul.py     потоковый парсер XML ЕГРЮЛ (iterparse, zip/папки), фильтры
  checko.py    дообогащение контактами: API + HTML, троттлинг и backoff на 429
  models.py    модель Company и плоская строка для выгрузки
  export.py    CSV (utf-8-sig) и Excel (openpyxl)
  pipeline.py  оркестрация ЕГРЮЛ → фильтр → обогащение
  cli.py       консольный интерфейс
webapp/        Flask: форма, прогресс, таблица, скачивание
tests/         pytest + синтетическая фикстура ЕГРЮЛ
```

## Тесты

```bash
python -m pytest -q
```

Покрыто офлайн: сопоставление ОКВЭД (включая граничные случаи иерархии),
парсер ЕГРЮЛ (фильтр по основному ОКВЭД и статусу, старый/новый формат тегов),
извлечение контактов из HTML/JSON, экспорт CSV/Excel.

## Ограничения и заметки

- **HTML-парсинг checko — best-effort.** Контакты на checko могут быть скрыты
  за подпиской, а вёрстка/селекторы меняются. Если HTML-режим возвращает пусто,
  это ожидаемо — надёжный путь это API. Селекторы в `checko.py`
  (`extract_contacts_from_html`) при необходимости калибруются на реальной
  сохранённой странице.
- **Ключи ответа API** checko зависят от тарифа; разбор в
  `_extract_contacts_from_json` написан терпимо (ищет блок «Контакты» и типовые
  ключи `Тел`/`Емэйл`/`Сайт`), но стоит сверить с вашим тарифом.
- Соблюдайте лимиты и условия использования checko/ФНС; для больших объёмов
  используйте API и разумный `--delay`.
